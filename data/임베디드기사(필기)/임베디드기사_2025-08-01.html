문제 10

유닉스 표준 시그널에서 시그널의 명칭과 발생 및 용도를 짝지은 것으로 옳지 않은 것은? [완전 신출]

 

① SIGTSTP는 CTRL+Z로 생성하여 터미널을 정지시키는 문자이다.
② SIGHUP는 터미널에서 접속이 끊겼을 때 CTRL+Q로 프로세스를 재시작한다.
③ SIGINT는 CTRL+C로 실행을 중지시키는 문자이다.
④ SIGQUIT는 CTRL+⧹로 종료 요청과 함께 코어 덤프를 생성한다.

 

더보기

정답: ②

해설:
SIGHUP는 Hangup 시그널로 전화선이 끊어졌을 때 발생한다. 즉, 디폴트 액션은 종료를 취하며, 변화된 내용을 적용하기 위해 재시작할 때 사용하며, 입력 명령어는 따로 존재하지 않는다. 또한, CTRL+Q라는 단축키는 존재하지도 않는다.

문제 11

리눅스의 SIGCHLD 시그널에 대한 설명으로 옳지 않은 것은? [완전 신출]

 

① 자식 프로세스가 좀비가 되는 것을 막기 위해서 wait 또는 waitpid 함수를 사용한다.
② 자식 프로세스가 종료될 경우 종료 상태를 부모 프로세스에게 보내지 않는다.
③ 자식 프로세스가 종료되면 SIGCHLD_HANDLER함수를 통해 시그널 핸들러를 수행한다.
④ 자식보다 부모가 먼저 종료될 경우 데몬 프로세스가 새로운 부모 프로세스가 되어 고아 프로세스가 작업을 마치고 종료될 수 있도록 한다.

 

더보기

정답: ②

해설:
자식 프로세스가 종료될 경우 종료 상태를 부모에게 자동으로 보낸다. 이것이 SIGCHLD 시그널이다. 하지만, 자식 프로세스에 발생한 결함은 부모에게 전파되지 않는다. 반면, 스레드에서는 자식 스레드에 결함 발생시 부모 스레드로 전파된다.

다음 리눅스 명령어 실행 중 일반 사용자 계정인 user 계정으로 로그인하여 퍼미션 인증 결과 다음과 같은 실행 결과가 도출되고, 비밀번호를 변경할 수 없는 상태라고 한다. 파일 비밀번호 변경을 위해서 입력해야 하는 명령어로 옳은 것은? [완전 신출]
┌─ [보기] ─────────────────────────────────────────┐
│ [root@localhost tmp] #touch file1 file2
│ -rwrx-rw—r 1 root root 0 2020년 11월 20 16:40 file1
│ -rw-r-xr-x 1 root root 0 2020년 11월 20 16:40 file 2
└──────────────────────────────────────────────────┘

 

① chown 4764 file1 chown u+s file 2
② chmod 764 file1 chmod u+s file 2
③ chmod 4764 file1 chmod u+s file 2
④ chown 764 file1 chown u+s file 2

 

더보기

정답: ③

해설:
세부 구문이나 조건의 정확도는 100% 장담까지는 못하나 인터넷 서칭하다가 매우 흡사한 구문이 있어 생각난 문제이다. 일단 4000번은 SetUID의 특별한 퍼미션에 해당하는 절대 표현 모드이므로 무조건 1,3번 중 하나가 답이다. 일반 퍼미션(764,655 등)으로는 비밀번호 수정 권한을 부여할 수가 없다. 또한, chown은 권한을 허가하는 명령어가 아닌 파일 또는 디렉토리의 소유자 그룹 변경 명령어이므로 3번이 답이 된다.
